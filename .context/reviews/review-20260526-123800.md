## Findings
### Finding 1
- Severity: medium
- Category: test-gap
- Summary: `scripts/run-validations.mts` does not execute a large set of shipped validators, so whole-codebase regression runs can report green while important coverage never runs.
- Evidence: `scripts/run-validations.mts` lists 23 validation scripts, but the repo currently contains 33 `validate-*.mts` files. The missing set includes active-looking suites such as `validate-learned-rule-draft-edge-cases.mts`, `validate-vazir-confidence-and-subsections.mts`, `validate-vazir-consolidate-handler-wiring.mts`, `validate-vazir-fallow-fossil-bridge.mts`, `validate-vazir-fallow-recurrence.mts`, `validate-vazir-fossil-footer.mts`, `validate-vazir-fossil-timeouts.mts`, `validate-vazir-live-reload.mts`, `validate-vazir-overlay-reader.mts`, and `validate-vazir-tracker-resolution.mts`.
- Recommendation: Either wire each maintained validator into `scripts/run-validations.mts` or explicitly mark/archive the ones that are not part of the supported regression suite.
- Rule candidate: When a validation script is intended to guard shipped behavior, include it in the aggregate validation runner or clearly mark it as manual-only.

### Finding 2
- Severity: low
- Category: dead-code
- Summary: `scripts/validate-vazir-complete-story-debug.mts` is an unreferenced duplicate debug harness with committed `DEBUG` logging.
- Evidence: Repo search found no references to `validate-vazir-complete-story-debug.mts` outside the file itself, and the file still contains `console.log("DEBUG ...")` statements at lines 348-350. The main suite already has `scripts/validate-vazir-complete-story.mts`, so the debug copy adds maintenance surface without being part of routine verification.
- Recommendation: Remove the debug validator, or rename and document it as a manual troubleshooting tool outside the automated suite.
- Rule candidate: Remove or quarantine one-off debug harnesses once the real regression test exists.

### Finding 3
- Severity: low

- Summary: Merge-tool backup files are still present under tracked source directories, creating noise and risking accidental drift against the real implementations.
- Evidence: The source tree still contains `.pi/extensions/vazir-tracker/chrome.ts-baseline`, `.pi/extensions/vazir-tracker/chrome.ts-merge`, `.pi/extensions/vazir-tracker/chrome.ts-original`, the corresponding `index.ts-*` and `vcs.ts-*` files, plus `.pi/lib/vazir-helpers.ts-baseline|merge|original`.

- Rule candidate: Do not commit merge-tool backup files (e.g., `.baseline`, `.merge`, `.original`) to the repository; delete them or add them to `.gitignore`.
