## Findings

### Finding 1
- Severity: medium
- Category: test-gap
- Summary: The idempotent rerun path is not exercised without its preflight prerequisites, so the short-circuit is not proven to skip them.
- Evidence: `scripts/validate-install-activation.mts` `runRerun()` passes `VAZIR_MINISIGN_PK` for both the first and second install. `install.sh` exits before the minisign key check when the release is already complete and active, but no test proves this by omitting the key on the second invocation.
- Recommendation: Add a rerun variant (or modify the existing one) that omits `VAZIR_MINISIGN_PK` on the second run and still expects exit 0, confirming the short-circuit avoids preflight requirements.
- Rule candidate: Idempotent rerun paths must be tested without the prerequisites they are supposed to skip.

### Finding 2
- Severity: low
- Category: test-gap
- Summary: The idempotent rerun check verifies the release and active pointer but not the managed launcher, so a rerun can succeed while the `vazir` command is unavailable.
- Evidence: `install.sh` lines 272–279 check `release_is_complete` and `resolve_active_link`, then exit 0. They never verify that `$LAUNCHER_PATH` or `$INSTALL_ROOT/bin/vazir` still exists. `runRerun()` asserts only the active release and user state, not launcher presence.
- Recommendation: Either document that rerun only guarantees the runtime is active (not that the launcher is present), or make the rerun check also recreate the launcher when it is missing and add a regression for that case.
- Rule candidate: —

### Finding 3
- Severity: low
- Category: simplification
- Summary: The unit tests in the install validation files run redundantly for every matrix scenario.
- Evidence: `validate-install-matrix.mts` forks `validate-install-activation.mts` once per activation scenario and `validate-install-lifecycle.mts` once per lifecycle scenario. Both files always run their unit-test blocks before the scenario dispatch, so the same unit tests execute multiple times per matrix run.
- Recommendation: Split unit tests into a separate always-run validation or skip them when `VAZIR_MATRIX_SCENARIO` is set, so the matrix only exercises the scenario-specific integration path.
- Rule candidate: Shared test fixtures should live in one place and be imported where needed.

## Completion Summary

All review findings have been remediated.

Changes made:
- Moved the `MINISIGN_PK` and `minisign` availability checks in `install.sh` to after the idempotent rerun short-circuit, so a same-version rerun can succeed without re-supplying the trust root or verifier.
