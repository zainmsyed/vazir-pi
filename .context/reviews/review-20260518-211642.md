## Findings

### Finding 1
- Severity: critical
- Category: regression
- Summary: Bulk deletion during review extraction accidentally removed eleven story-closeout helper functions from `vazir-context/index.ts` that are still referenced by `/complete-story` and `agent_end`.
- Evidence: `listCompletionBlockers` is referenced at lines 445 and 1121; `resolveStoryForCompletion` at line 1116; `buildCompleteStoryInstruction` at line 1129; `promptReadyCloseout` at lines 451 and 1141; `resolveContextPersistenceChoice` at lines 471 and 1162; `startLearnedRuleCloseout` at lines 474 and 1165; `finishLearnedRuleCloseout` at line 423; `completeStoryNow`, `completeStoryAndCommitNow`, `finalizeStoryCloseout`, and `promptLearnedRulePromotion` are all called transitively by the remaining closeout flow but no longer exist in the file.
- Recommendation: Restore the deleted functions to `vazir-context/index.ts`. Run a reference check (`grep -n 'function\|const'`) after any bulk deletion to confirm no referenced symbols were dropped.
- Rule candidate: When performing bulk deletions with automated scripts, always run a smoke test or grep for remaining references before committing.

### Finding 2
- Severity: high
- Category: bug
- Summary: `syncReviewSummaryAndPromoteRules` is registered twice for `session_before_compact` and `session_shutdown` — once in `vazir-context` and once in `vazir-review`.
- Evidence: `vazir-context/index.ts` calls `syncReviewSummaryAndPromoteRules` in both session handlers. `vazir-review/index.ts` registers its own identical handlers for the same events.
- Recommendation: Remove `syncReviewSummaryAndPromoteRules` from `vazir-context`'s `session_before_compact` and `session_shutdown` handlers; let `vazir-review` own review lifecycle sync.
- Rule candidate: When extracting lifecycle handlers into a new extension, remove the original registration to avoid duplicate event processing.

### Finding 3
- Severity: high
- Category: regression
- Summary: The manual-review `agent_end` closeout in `vazir-review/index.ts` does not handle `close-commit` (or `close` for story-attached reviews), silently dropping the user's choice.
- Evidence: `vazir-review/index.ts` `agent_end` only checks `if (decision === "close")` before notifying. The original `vazir-context` code called `resolveContextPersistenceChoice`, `completeStoryNow`, and `completeStoryAndCommitNow` for story-attached reviews. These paths are absent after extraction.
- Recommendation: Restore story completion handling in `vazir-review`'s manual-review closeout by importing or replicating the required closeout helpers.
- Rule candidate: Extracted closeout flows must preserve all terminal branches of the original state machine, including commit-and-close paths.

### Finding 4
- Severity: medium
- Category: dead-code
- Summary: `vazir-context/helpers.ts` retains full copies of review-specific types and helpers that now live in `vazir-review/helpers.ts` and are no longer imported by `vazir-context/index.ts`.
- Evidence: `parseReviewFrontmatter`, `reviewFindingsFromFile`, `syncReviewSummaryAndPromoteRules`, `createReviewDraft`, `buildReviewInstruction`, `reviewFileTemplate`, `collectReviewAggregates`, `writeReviewSummary`, `appendFallowToComplaintsLog`, and associated types (`ReviewDraft`, `ReviewFrontmatter`, etc.) are duplicated. The `REVIEW_WORKFLOW_HELPERS` facade also points to these stale local copies.
- Recommendation: Remove dead review helpers from `vazir-context/helpers.ts` in a dedicated cleanup pass.
- Rule candidate: After extracting helpers to a new module, delete the original copies to prevent drift and confusion.

### Finding 5
- Severity: low
- Category: simplification
- Summary: `registerReviewScaffold` is an empty no-op function that is still imported by `vazir-context/index.ts` and called by both extensions at startup.
- Evidence: `vazir-review/index.ts` exports `registerReviewScaffold(_pi: ExtensionAPI): void { /* Intentionally empty */ }`. `vazir-context/index.ts` imports and calls it.
- Recommendation: Remove the import and call from `vazir-context/index.ts`; keep the export in `vazir-review` only until all consumers are updated.
- Rule candidate: Remove no-op registration hooks once the real behavior has migrated to the owning extension.
