- Category: regression

- Rule candidate: When extracting a large block of helpers from a module, run a reference check for every removed function name against the remaining code in that module before committing the extraction.

### Finding 2
- Severity: high
- Category: regression
- Summary: `validate-vazir-review-loop.mts` fails because it loads only the `vazir-context` extension but the `/review` command now lives in `vazir-review`.
- Evidence: The script calls `loadExtensionModule<{ default: (pi: any) => void }>("vazir-context")` and then creates a harness with only that register function. After story-020, `harness.getCommand("review")` returns `undefined`, so the assertion `assert(Boolean(review), "review command was not registered")` throws. Running `node scripts/validate-vazir-review-loop.mts` fails with `Error: review command was not registered`.
- Recommendation: Update `validate-vazir-review-loop.mts` to also load `vazir-review` via `loadExtensionModule` and pass both register functions to `createPiHarness`, then rerun the script.
- Rule candidate: When extracting a command into a new extension, update every validation script that exercises that command to load the new extension module alongside the original entrypoint.
