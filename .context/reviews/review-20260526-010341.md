## Findings
### Finding 1
- Severity: high
- Category: regression
- Summary: Restarted learned-rule closeout always falls back to plain `close`, so a user who originally chose `Close story and commit all` can lose the commit on rerun.
- Evidence: `.pi/extensions/vazir-context/index.ts:1090-1098` clears `pendingCompleteStoryRequests` on `session_shutdown`, so `resumePersistedLearnedRuleCloseout()` in `.pi/extensions/vazir-context/complete-story.ts:596-617` cannot recover the prior `closeIntent`. It therefore uses `previousPending?.closeIntent ?? "close"` at line 608, and `finishLearnedRuleCloseout()` later finalizes with `pendingCompleteStory.closeIntent ?? "close"` at lines 713 and 761/798. The restarted validator only exercises `selectResponses: ["Close story now"]` in `scripts/validate-vazir-complete-story.mts:544-547`, so this close-and-commit regression is currently untested.
- Recommendation: Persist the selected close intent alongside the learned-rule draft (or in another restart-safe file) and restore it during resumed learned-rule closeout before finalizing the story.
- Rule candidate: When a restart-resumable workflow defers a terminal action, persist the chosen terminal intent with the resumable artifact instead of relying on in-memory state.

### Finding 2
- Severity: medium
- Category: test-gap
- Summary: The new restart coverage proves only the plain-close resume path, leaving the commit-preserving restart contract uncovered.
- Evidence: The added restart scenario in `scripts/validate-vazir-complete-story.mts:539-594` resumes a persisted learned-rule draft only after the initial choice `"Close story now"`; none of the restart scenarios choose `"Close story and commit all"` and then assert that the resumed closeout still commits. The non-restart commit scenarios elsewhere in the file do not cover this persisted re-entry branch.
- Recommendation: Add a restart scenario that selects `Close story and commit all`, seeds a learned-rule draft, reruns `/complete-story`, and asserts the resumed closeout both finishes and commits using the expected VCS backend.
- Rule candidate: Add restart coverage for every persisted branch whose final side effect differs materially, especially when one branch writes to VCS and another does not.
