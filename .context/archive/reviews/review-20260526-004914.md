## Findings
### Finding 1
- Severity: high
- Category: regression
- Summary: `/complete-story` no longer resumes a persisted learned-rule closeout draft after a restart, so an interrupted closeout falls back to the generic ready prompt instead of continuing from the saved closeout phase.
- Evidence: `.pi/extensions/vazir-context/index.ts:1090-1098` clears `pendingCompleteStoryRequests` on `session_shutdown`, and `createCompleteStoryController.handleCommand()` in `.pi/extensions/vazir-context/complete-story.ts:905-922` goes straight from the ready prompt to starting a new learned-rule closeout without checking for an existing draft. The pre-extraction implementation in `.pi/extensions/vazir-context/index.ts-original:1505-1518` explicitly resumed `learnedRuleCloseoutDraftPath(...)` and called `finishLearnedRuleCloseout(...)` immediately.
- Recommendation: Restore the persisted-draft resume path in `handleCommand()` so rerunning `/complete-story` re-enters learned-rule closeout when `.context/reviews/<story>-learned-rule-closeout.json` already exists.
- Rule candidate: When a workflow persists an intermediate closeout artifact, `/complete-story` must check for it and resume that phase before offering a fresh closeout prompt.

### Finding 2
- Severity: medium
- Category: test-gap
- Summary: The new restart coverage still misses the learned-rule-draft re-entry path and even codifies state loss for the review restart case.
- Evidence: `scripts/validate-vazir-complete-story.mts:558-582` asserts that, after shutdown, rerunning `/complete-story` should create a second review file instead of resuming the earlier closeout state. The only new persisted re-entry scenario at `scripts/validate-vazir-complete-story.mts:1067-1113` covers readiness recovery only; the validator never seeds a learned-rule closeout draft and reruns the command to prove the persisted closeout phase resumes.
- Recommendation: Add a restart scenario that writes a valid learned-rule closeout draft, reruns `/complete-story`, and asserts the promotion/skip closeout resumes without creating a fresh review or re-sending the earlier closeout instruction.
- Rule candidate: Every persisted workflow phase needs a restart test that proves rerunning the command resumes that exact phase instead of restarting from an earlier prompt.
