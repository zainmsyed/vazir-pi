### Finding 3
- Severity: low
- Category: bug
- Summary: showMarkdownViewer computes visibleRows once at construction time and won't adapt if the terminal is resized while the overlay is open
- Evidence: In `.pi/lib/vazir-ui.ts`, `const visibleRows = Math.max(5, (process.stdout.rows || 24) - 10);` is evaluated once inside the factory closure. If the user resizes the terminal after opening a story, the `ScrollableMarkdown` window stays at the old height.
- Recommendation: Move the `visibleRows` calculation into `render()` so it re-evaluates on every frame, or at least into `handleInput` so keyboard-triggered re-renders pick up the new size.
- Rule candidate: —

### Finding 4
- Severity: low
- Category: simplification
- Summary: stripAnsi regex in padOrTruncate only matches SGR sequences (ending in m) and will miss other ANSI escape codes
- Evidence: `.pi/lib/vazir-ui.ts` line 119: `str.replace(/\x1b\[[0-9;]*m/g, "")`. This misses erase-line (`\x1b[K`), cursor movement (`\x1b[10D`), and OSC sequences. While pi-tui's Markdown and SelectList currently emit only SGR codes, a future theme change or pi upgrade could introduce others, causing `padOrTruncate` to miscompute visible width and break border alignment.
- Recommendation: Broaden the regex to `/\x1b\[[0-9;?]*[A-Za-z]/g` (covers all CSI sequences) or import/use a proper ANSI strip helper if one becomes available in pi-tui.
- Rule candidate: When stripping ANSI for width calculations, use a regex that matches the full CSI range (`\x1b[...letter`) rather than only SGR (`\x1b[...m`).
