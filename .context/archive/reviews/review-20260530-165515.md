## Summary

Story-042 rewrites `README.md` as a concise quickstart guide. The resulting README is clear, well-structured, and centered on the core workflow. However, implementation expanded beyond the stated scope by modifying `.pi/extensions/vazir-tracker/chrome.ts` to add a README selectable item in the help overlay. Two bugs were introduced in that out-of-scope change: an unguarded `fs.readFileSync` call and missing test coverage for the new branch.

---

## Findings

### Finding 1
- Severity: medium
- Category: workflow
- Summary: Story-042 explicitly scopes to `README.md` only, with "Any code or extension files" out of scope. The `chrome.ts` change adding README as a selectable help-overlay item is a scope violation.
- Evidence: Story-042 Out of scope section lists "Any code or extension files" and "Adding new commands". The `showCommandHelp` function in `.pi/extensions/vazir-tracker/chrome.ts` was modified to import `showMarkdownViewer`, prepend a README item to the SelectList, and add a `pick === "README"` branch that reads the file and opens a markdown viewer.
- Recommendation: If the README-in-overlay feature is desired, track it as a follow-up story rather than adding it ad-hoc during a README-only story. Revert the `chrome.ts` change or spin it out into its own story.
- Rule candidate: When a user requests an out-of-scope feature during implementation, record it as a new story instead of silently expanding the current story's scope.

### Finding 2
- Severity: medium
- Category: bug
- Summary: The README selection handler in `showCommandHelp` calls `fs.readFileSync` without a try/catch. If `README.md` is missing, the overlay crashes instead of gracefully falling back.
- Evidence: `.pi/extensions/vazir-tracker/chrome.ts` line ~862: `const content = fs.readFileSync(readmePath, "utf-8");` with no error handling. A missing README would throw `ENOENT` inside the async `showCommandHelp` flow, leaving `commandHelpOpen = true` and potentially blocking the shortcut.
- Recommendation: Wrap the read in a try/catch. If the file is missing, call `ctx.ui.notify("README.md not found", "warning")` and `continue` to return to the list.
- Rule candidate: When reading user-facing files in an interactive overlay, always guard against missing files so the UI doesn't crash.

### Finding 3
- Severity: low
- Category: test-gap
- Summary: The help overlay's new README selection path is not covered by any validation script.
- Evidence: `scripts/validate-vazir-help-shortcut.mts` tests shortcut registration and guard behavior but does not assert that the items array includes a README entry or that selecting it opens `showMarkdownViewer`. The branch is only reachable through the `while (true)` loop in `showCommandHelp`, which is not exercised in tests.
- Recommendation: Add an assertion in `validate-vazir-help-shortcut.mts` that the list items include a README entry, or add a mock `ui.custom` scenario that selects "README" and asserts `showMarkdownViewer` is invoked.
- Rule candidate: When adding a new conditional branch to an interactive UI flow, add a regression test that exercises the new branch directly.
