## Findings

### Finding 1
- Severity: critical
- Category: bug
- Summary: `processCompleteStoryReviewCloseout` re-prompts on every `agent_end` after the user already chose to close
- Evidence: In `agent_end` (`.pi/extensions/vazir-context/index.ts`), the `if (reviewFilePath)` branch unconditionally calls `processCompleteStoryReviewCloseout`. That function always runs `promptReviewFindingsCloseout`, even when `closeIntent` was already set in a previous turn. After the user chooses "Close story now" in review closeout, `closeIntent` is stored. On the next `agent_end` (after the agent writes the candidates file), the code re-enters `processCompleteStoryReviewCloseout` and re-prompts the user for review closeout instead of going straight to mini-consolidate.
- Recommendation: Guard the `processCompleteStoryReviewCloseout` call so it only runs when `!pendingCompleteStory.closeIntent`. If `closeIntent` is already set, skip straight to the mini-consolidate branch.
- Rule candidate: When deferring closeout across multiple `agent_end` turns, guard the intermediate closeout prompt so it does not re-fire after the user has already made a choice

### Finding 2
- Severity: medium
- Category: bug
- Summary: Story can be stranded in limbo if the agent never writes the candidates file
- Evidence: In `agent_end`, when `miniConsolidatePhase === "sent"` but the candidates file does not exist, the code falls through both branches and returns without doing anything. The `pendingCompleteStoryRequests` entry remains. On every subsequent `agent_end`, the same thing happens. The story never closes.
- Recommendation: Add a fallback: if `miniConsolidatePhase === "sent"` and the file still doesn't exist after one turn, either re-send the instruction (reset `miniConsolidatePhase`) or close with a warning.
- Rule candidate: Multi-turn deferred closeouts need a timeout or retry fallback so the story does not hang indefinitely

### Finding 3
- Severity: low
- Category: dead-code

- Evidence: `const candidatesPath = miniConsolidateCandidatesPath(cwd, storyLabel);` is declared but never referenced in the returned instruction or elsewhere in the function.
- Recommendation: Remove the unused variable.
- Rule candidate: —

### Finding 5
- Severity: low
- Category: workflow
- Summary: Mini-consolidate prompt text says "Promote both? Skip both?" even with a single candidate
- Evidence: The prompt text is hardcoded as `"Promote both? Skip both? Or enter numbers to select:"`. When only one candidate exists, the options are `"Promote"`, `"Skip all"`, `"Promote 1"`, which mismatches the prompt.
- Recommendation: Make the prompt text dynamic based on candidate count (e.g. "Promote all? Skip all? Or enter numbers to select:").
- Rule candidate: Picker prompt text should match the actual option count so the user is not confused

### Finding 6
- Severity: medium
- Category: test-gap
- Summary: Validation script only tests the "no candidates" path
- Evidence: `scripts/validate-vazir-complete-story.mts` was updated to write `"No candidates found."` and emit an extra `agent_end`. It does not cover: (a) candidates found + user promotes, (b) candidates found + user skips, (c) non-interactive session with candidates, (d) the review re-prompt bug from Finding 1.
- Recommendation: Add at least one scenario that writes real candidates, asserts the picker is shown, asserts promotion to `system.md`, and asserts the story closes afterwards.
- Rule candidate: New closeout flows need coverage for both happy paths and edge paths (skip, empty, non-interactive)

### Finding 7
- Severity: low
- Category: simplification
- Summary: `runMiniConsolidateCloseout` duplicates the final close logic four times
- Evidence: The pattern `pendingCompleteStoryRequests.delete(cwd); if (closeIntent === "close-commit") { completeStoryAndCommitNow(...) } else { completeStoryNow(...) }` appears in the "no candidates", "no UI", "skip all", and "promote" branches.
- Recommendation: Extract a helper like `finalizeStoryCloseout(ctx, storyPath, closeIntent)`.
- Rule candidate: Extract repeated closeout sequences into a single helper to prevent drift
