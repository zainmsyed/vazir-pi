## Findings
### Finding 1
- Severity: medium
- Category: bug
- Summary: Missing or already-resolved idea references perform `/plan` side effects before validation aborts.
- Evidence: The handler creates or refreshes `intake-brief.md`, seeds design files, may create `plan.md`, and emits planning notifications before parsing and validating `idea-NNN`. A missing or promoted reference therefore leaves planning artifacts behind even though no planning message is sent.
- Recommendation: Parse and validate the idea reference immediately after reading the command arguments, before writing any planning artifacts or changing pending plan state. Only continue into normal `/plan` setup after the referenced idea is confirmed `open`.
- Rule candidate: Validate command references before performing workflow side effects so rejected requests leave the workspace unchanged.

### Finding 2
- Severity: medium
- Category: regression
- Summary: Idea promotion tracking is discarded when generated stories require the existing plan-repair follow-up.
- Evidence: In `turn_end`, when `checkStoryPitfalls(cwd)` finds malformed generated stories, the handler sends a repair instruction and immediately deletes `pendingPlanRepairRequests`. After the repair turn produces valid stories, no seeded idea number remains, so `idea-NNN.md` stays `open` instead of becoming `promoted`.
- Recommendation: Preserve the pending plan request through the repair dispatch and promote only after a later turn observes the new story files as valid; keep repair attempts and the seeded idea reference together in the same state.
- Rule candidate: When a workflow has an automatic repair turn, preserve all completion metadata across the repair transition until the repaired output is verified.

### Finding 3
- Severity: medium
- Category: workflow
- Summary: The claimed conversational `plan this` mapping is not implemented or explicitly instructed by the extension; only literal `/plan idea-NNN` arguments are handled.
- Evidence: `parseIdeaReference()` accepts only the regex `^idea-(\d+)$`, and the planning instruction contains no guidance for resolving "plan this" after viewing an idea. The viewer also does not send an idea reference back into the agent conversation. Therefore the story's shorthand path depends on unverified model inference rather than a defined integration point.
- Recommendation: Add an explicit, scope-compliant instruction or event handoff that tells the agent that "plan this" after viewing an idea means `/plan idea-NNN`, and add a regression/smoke assertion for that mapping without introducing a second planning mechanism.
- Rule candidate: Conversational shorthand for a file-backed workflow must have an explicit handoff or instruction carrying the referenced file identity; do not rely on implicit UI state or model inference alone.
