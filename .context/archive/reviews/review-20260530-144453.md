## Findings
### Finding 1
- Severity: low
- Category: simplification
- Summary: `validateCommandDocsComplete` only checks that every `VAZIR_COMMAND_HELP` entry has a matching `CommandDoc`, but not the reverse. A stray `CommandDoc` without a corresponding `VAZIR_COMMAND_HELP` entry would go unnoticed at runtime.
- Evidence: The function iterates `VAZIR_COMMAND_HELP` and checks `VAZIR_COMMAND_DOCS.find(d => d.command === entry.command)`. There is no corresponding loop over `VAZIR_COMMAND_DOCS` checking `VAZIR_COMMAND_HELP`. The static validation script `validate-vazir-command-docs.mts` does check both directions, so the gap is only in the runtime helper.
- Recommendation: Make `validateCommandDocsComplete` bidirectional by also iterating `VAZIR_COMMAND_DOCS` and checking for matching help entries, or rename it to `validateHelpDocsHaveCommandDocs` to reflect the actual check.
- Rule candidate: When validating bidirectional consistency between two parallel data structures, check both directions so drift in either direction is caught.
