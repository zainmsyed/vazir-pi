## Findings
### Finding 1
- Severity: low
- Category: simplification
- Summary: The `/idea` handler duplicates the capture-prompt and `captureIdea()` call in both the direct-capture branch and the selector capture branch.
- Evidence: `.pi/extensions/vazir-context/index.ts` lines ~2038–2050 and ~2064–2080 both contain nearly identical loops over `ctx.ui.input`, empty-input retry, cancellation, `captureIdea()` call, and EEXIST handling.
- Recommendation: Extract a small `runIdeaCapturePrompt(cwd, ctx)` helper that prompts, retries, cancels, and writes the idea, then call it from both branches.
- Rule candidate: When the same capture/write sequence appears in two command branches, extract a single helper so fixes (e.g., notification wording, no-overwrite behavior) apply everywhere.

### Finding 2
- Severity: low
- Category: test-gap
- Summary: `scripts/validate-vazir-idea-browse.mts` exercises the custom-overlay selection path but does not exercise the `ctx.ui.select` fallback path for the view-list.
- Evidence: The browse test provides `ctx.ui.custom` and records `customSelectionCalls`; the capture validation script provides only `ctx.ui.select`, but it never opens the view list through the fallback.
- Recommendation: Add one test case in `validate-vazir-idea-browse.mts` (or a sibling script) that omits `ctx.ui.custom` and uses `ctx.ui.select` to choose "View existing ideas" and then an idea label, verifying the fallback path returns the correct value and opens the viewer.
- Rule candidate: When a shared helper has both a rich overlay path and a plain `select` fallback, regression tests should cover both paths because the fallback contains its own label-to-value mapping logic.

### Finding 3
- Severity: low
- Category: dead-code
- Summary: `scripts/validate-vazir-idea-browse.mts` declares and populates `selectCalls` but never reads it.
- Evidence: The `select` mock pushes to `selectCalls`, but every assertion uses `customSelectionCalls` and `viewerCalls` instead.
- Recommendation: Remove the unused `selectCalls` variable and the push in the `select` mock, or assert against it for the fallback-path test recommended in Finding 2.
