## Findings
### Finding 1
- Severity: high
- Category: bug
- Summary: Range scanning can leave the committed 3100–3199 range when the persisted port is below 3100.
- Evidence: `rangeCandidates(start)` computes `(start - PORT_RANGE_START + offset) % rangeSize` without normalizing a negative remainder. A persisted port such as 3000 produces candidates 3000 through 3099, even though the contract requires fallback only through 3100–3199.
- Recommendation: Normalize the modulo result to a non-negative value, or explicitly clamp out-of-range persisted ports to `PORT_RANGE_START` before generating candidates. Add a regression using a persisted port below the range.
- Rule candidate: When generating bounded cyclic candidates, normalize modulo results so negative starting offsets cannot escape the committed range.

### Finding 2
- Severity: medium
- Category: bug
- Summary: Live duplicate detection is Linux-specific and silently degrades to false on platforms without `/proc`.
- Evidence: `processHoldsPort` requires `/proc/net/tcp`, `/proc/net/tcp6`, `/proc/<pid>/fd`, and `readlinkSync`. The catch blocks return no inodes or `false`, so a live duplicate on Windows or another non-`/proc` platform is treated as a foreign holder and may trigger reassignment instead of returning duplicate metadata.
- Recommendation: Provide a portable ownership-verification strategy (or an explicit platform-supported implementation boundary) and add coverage for the fallback behavior so live-instance detection cannot silently violate the contract.
- Rule candidate: —

### Finding 3
- Severity: medium
- Category: test-gap
- Summary: The dead-PID regression does not exercise the stale-PID retry branch.
- Evidence: The validation closes the initial lease before calling `assignPort`, so the first direct bind succeeds and the code never reaches the `recordedPid` check followed by the second bind attempt. The story verification specifically requires dead-PID reclaim through bind retry.
- Recommendation: Make the test force the first candidate bind to fail, then release the holder before the retry (or inject a deterministic bind seam), and assert the retry succeeds without a notice.
- Rule candidate: Regression tests for retry logic should force the initial attempt to fail and independently verify the recovery attempt, rather than only testing the already-recovered final state.
