### Finding 2
- **Severity:** low
- **Category:** bug
- **Summary:** The checklist section regex in `checkStoryPitfalls` uses a lookahead `^#{1,2}\s` without the `m` (multiline) flag, making it unreachable. The `## ` alternative handles the common case but can match inside backticks or inline text, which would truncate the captured checklist section.
- **Evidence:** `.pi/extensions/vazir-context/index.ts:1012` — `const checklistMatch = content.match(/## Checklist[\s\S]*?(?=## |^#{1,2}\s|$)/);`. The `^` without the `m` flag only matches at the start of the string. A checklist item like `- [ ] Add support for \`## header\` parsing` would cause the regex to stop at the `## ` inside the backticks, excluding subsequent checklist items from validation.
- **Recommendation:** Replace the regex with the shared `readStorySectionByHeading` helper from `.pi/lib/vazir-helpers.ts`, which already uses the correct `^## ${heading}` with the `m` flag and computes the section body robustly. If keeping the inline regex, add the `m` flag and use `(?=\n## |$)` to avoid matching `## ` inside text.
- **Rule candidate:** When parsing markdown sections with regex, use the multiline flag (`m`) and anchor headings to line starts (`\n## ` or `^` with `m`) so inline text does not accidentally match section boundaries.

### Finding 3
- **Severity:** low
- **Category:** simplification
- **Summary:** `checkStoryPitfalls` in `index.ts` duplicates the same status, section, and checklist checks already implemented in `validateStoryFile` in `.pi/lib/vazir-helpers.ts`. The duplication means any future change to story validation rules (e.g., adding `Type:` validation or new required sections) must be updated in two places.
- **Evidence:** `.pi/extensions/vazir-context/index.ts:978-1040` — `checkStoryPitfalls` checks status, required sections, and checklist format. `.pi/lib/vazir-helpers.ts:712-770` — `validateStoryFile` checks the same fields with more robust section parsing and line-numbered issue reporting.
- **Recommendation:** Replace `checkStoryPitfalls` with a lightweight wrapper around `validateStoryFile` that filters the returned issues to the simple string format the plan guard needs. This reduces maintenance burden and ensures the `/plan` guard and `/implement` guard use the same validation rules.
- **Rule candidate:** When a lightweight validation check duplicates logic from a shared validator, delegate to the shared validator and transform the output, rather than maintaining two independent implementations.
