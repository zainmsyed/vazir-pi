## Findings
### Finding 1
- Severity: high
- Category: bug
- Summary: The `fossil git export` command constructed by `buildFossilGitExportPlan` used incorrect syntax (`fossil git export <repo> <mirror> --autopush`) that the real Fossil binary rejects, causing both `/vcs-mirror-sync` and the closeout auto-export to fail in production.
- Evidence: The user reported `Mirror auto-sync failed: unrecognized command-line option or missing argument: --autopush`. Fossil's actual syntax is `fossil git export [MIRROR] [OPTIONS]` where `--autopush URL` requires a URL argument. The repository path is inferred from the current checkout, not passed as an argument.
- Recommendation: Validate exported command text against the real tool's help output or man page before relying on it in production. When tests use fake binaries, ensure the fake accurately models the real tool's argument parsing.
- Rule candidate: When tests replace a real external tool with a fake binary, the fake must match the real tool's accepted argument syntax so the test suite does not give false confidence.

### Finding 2
- Severity: medium
- Category: test-gap
- Summary: The mirror-sync and mirror-autosync validation scripts used fake Fossil binaries that accepted the incorrect `--autopush` syntax, masking the real bug until user execution.
- Evidence: `scripts/validate-vazir-vcs-mirror-sync.mts` and `scripts/validate-vazir-vcs-mirror-autosync.mts` both created fake `fossil` binaries with a `git)` case that blindly accepted any arguments after `export`. The real Fossil binary would have rejected the same invocation.
- Recommendation: When validating VCS tool integrations, run at least one smoke test against the real installed binary (or its documented syntax) to catch argument mismatches that fakes may hide.
- Rule candidate: Validation of VCS restore and undo behavior should exercise real repositories with actual tool commands rather than only stubs, because stubs can mask semantic mismatches between assumed and actual tool behavior.
