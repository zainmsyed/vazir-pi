## Findings
### Finding 1
- Severity: high
- Category: regression
- Summary: `/complete-story` still routes closeout orchestration through visible user messages, so choosing a close path leaks raw control instructions into the chat instead of keeping the user inside the expected closeout prompt flow.
- Evidence: `.pi/extensions/vazir-story/index.ts` now calls `pi.sendUserMessage(instruction, { deliverAs: "followUp" })` in `startLearnedRuleCloseout`, and `.pi/extensions/vazir-review/index.ts` does the same in `startReviewFlow` and both review-remediation branches. Pi's `docs/extensions.md` explicitly documents `pi.sendUserMessage()` as sending an actual user message that "appears as if typed by the user." The updated validation in `scripts/validate-vazir-complete-story.mts` now asserts `sentUserMessages.length === 1` / `=== 2` / `=== 3` across these flows, which locks in the visible-chat behavior instead of catching it as a regression.
- Recommendation: Move `/complete-story` orchestration back onto a non-user-visible channel or keep the state-machine continuation inside command/session state so the agent can do the background work without printing raw instructions into the transcript. Update the validation contract to assert the user sees the closeout/review prompts, not visible follow-up control text.
- Rule candidate: When a workflow depends on background agent orchestration, do not route control instructions through a user-visible message channel that renders as chat content.

- Recommendation: Remove the unused constant and the unused readiness-instruction helper so the code matches the current flow and future refactors do not mistake them for live paths.
- Rule candidate: —

### Finding 3
- Severity: medium
- Category: test-gap
- Summary: The new regression coverage protects draft-resume behavior but still does not exercise the real user-facing requirement that `/complete-story` must not dump orchestration text into the chat transcript.
- Evidence: `scripts/validate-vazir-complete-story.mts` now covers valid saved drafts, invalid draft regeneration, review gating, and learned-rule promotion, but every updated assertion treats visible `sentUserMessages` as the expected success path. There is no scenario asserting that the user remains in the interactive closeout loop without an extra visible instruction turn after selecting `Close story now`, `Close story and commit all`, or `Start code review before closing`.
- Recommendation: Add a regression scenario at the command/UI boundary that fails if `/complete-story` emits visible orchestration prose instead of returning the user to the expected interactive prompt sequence.
- Rule candidate: Background orchestration regressions need a user-visible contract test that fails when internal control text leaks into the chat surface.
