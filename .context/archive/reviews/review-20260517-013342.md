## Findings

### Finding 1
- **Severity:** medium  
- **Category:** test-gap  
- **Summary:** `prepareLearnedRulesForConsolidation(cwd)` has no direct unit test coverage. It is validated only indirectly through the `/consolidate` handler wiring test, which asserts confidence annotations and subsections appear but does not verify that deduplication, confidence scoring, and kind categorization all happen in a single I/O pass.  
- **Evidence:**
  - `.pi/extensions/vazir-context/helpers.ts` line ~2717: `prepareLearnedRulesForConsolidation` reads `system.md` once, applies dedupe + confidence + kind, and writes once.
  - `scripts/validate-vazir-consolidate-handler-wiring.mts` asserts `system.md` gains `<!-- confidence: high -->` and `### From failures` after the handler runs, but it does not assert that dedupe happened or that only one write occurred.
  - `scripts/validate-vazir-confidence-and-subsections.mts` tests `updateRuleConfidence` and `organizeLearnedRules` in isolation, not the combined helper.
- **Recommendation:** Add a direct unit test for `prepareLearnedRulesForConsolidation` that seeds `system.md` with duplicate rules, missing confidence, and missing kind, then asserts all three are fixed in one call with a single observable file write.
- **Rule candidate:** When extracting a combined helper that merges multiple previously separate operations, add a direct unit test that exercises all constituent operations together, not just the end-to-end consumer.

### Finding 2
- **Severity:** low  
- **Category:** test-gap  
- **Summary:** `createReviewDraft` with `fallowFindings` is not directly tested. The `reviewFileTemplate` function is tested with and without findings, but the full draft creation path that passes findings through `createReviewDraft` → `reviewFileTemplate` → file write is not exercised.  
- **Evidence:**
  - `scripts/validate-vazir-fallow-signal-sources.mts` calls `reviewFileTemplate(..., [{ rule: "dead-code", location: "src/example.ts:1", summary: "dead export" }])` directly.
  - It does not call `createReviewDraft({ fallowFindings: [...] })` and assert the written review file contains the pre-populated findings.
  - The design-compliance validation (`validate-vazir-review-design-compliance.mts`) tests `createReviewDraft` for UI flags but not for `fallowFindings`.
- **Recommendation:** Extend `validate-vazir-fallow-signal-sources.mts` (or add a dedicated test) that calls `createReviewDraft` with `fallowFindings` and asserts the written file contains the pre-populated `## Fallow Findings` entries.
- **Rule candidate:** When adding a new optional field to a data structure that flows through a draft creation function, test the full draft path end-to-end, not just the terminal template function.
