## Findings
### Finding 1
- Severity: medium
- Category: test-gap
- Summary: A successful aggregate run can omit the JJ exact-restore validation when `jj` is unavailable.
- Evidence: `scripts/run-validations.mts` conditionally skips `validate-vazir-jj-exact-restore.mts` when `jj --version` fails. The recorded `npm test` pass therefore verifies the port registration and the rest of the available suite, but not exact-restore behavior in this environment.
- Recommendation: Keep the explicit skip for environments without JJ, but require a separate JJ-enabled CI or release validation job and document that the aggregate green result is conditional on tool availability.
- Rule candidate: Optional external-tool validations should report explicit skips and be required separately in a tool-enabled validation environment.
