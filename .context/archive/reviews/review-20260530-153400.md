## Summary

Story-041 replaces the static Ctrl+? help path with a selectable command list backed by the real `VAZIR_COMMAND_DOCS` registry, wires selection to the detail overlay, adds a quickstart banner, and cleans up the `/test-help` prototype. The implementation is clean and follows established patterns. Four findings were identified: one regression in a stale validation script, two bugs in edge-case guard handling, and one test gap for the new shortcut behavior.

---

## Findings

### Finding 1
- Severity: medium
- Category: regression
- Summary: `scripts/validate-vazir-overlay-reader.mts` imports and tests `showScrollableOverlay`, which was removed from `.pi/extensions/vazir-tracker/chrome.ts` in story-041. The script will crash at runtime because the export no longer exists.
- Evidence: The script does `const { showScrollableOverlay, showScrollableText } = chromeModule` and asserts `typeof showScrollableOverlay === "function"`. A grep of `chrome.ts` confirms `showScrollableOverlay` has been deleted. The entire file is now dead code that produces a false failure.
- Recommendation: Delete `scripts/validate-vazir-overlay-reader.mts` or rewrite it to exercise the new `showCommandHelp` overlay path (banner, SelectList, loop-back, Escape-to-close).
- Rule candidate: After removing a public function, update or delete validation scripts that reference it so the test suite does not produce false failures.

### Finding 2
- Severity: medium
- Category: bug
- Summary: `showCommandHelp` uses optional chaining in its guard (`ctx.ui?.custom`) but then calls `ctx.ui.notify` without optional chaining, which throws when `ctx.ui` is undefined.
- Evidence: `.pi/extensions/vazir-tracker/chrome.ts` line ~809: `if (!ctx.hasUI || typeof ctx.ui?.custom !== "function") { ctx.ui.notify("Help overlay requires a TUI session", "info"); return; }`. If `ctx.ui` is undefined, the guard evaluates true, but `ctx.ui.notify` crashes.
- Recommendation: Change `ctx.ui.notify` to `ctx.ui?.notify`, or add `if (!ctx.ui) return;` before the notify call.
- Rule candidate: When using optional chaining to guard a property access, ensure all subsequent accesses on the same object inside the guarded block also use optional chaining or an explicit null check.

### Finding 3
- Severity: medium
- Category: bug
- Summary: `tearDownChromeSession` unsubscribes from terminal input but does not reset the module-level `commandHelpOpen` guard. If a session ends while the help overlay is open, Ctrl+? remains permanently blocked on the next session.
- Evidence: `.pi/extensions/vazir-tracker/chrome.ts` `tearDownChromeSession` sets `commandHelpInputUnsubscribe = null` but never sets `commandHelpOpen = false`. The flag persists across sessions because it is declared at module scope.
- Recommendation: Add `commandHelpOpen = false;` in `tearDownChromeSession` alongside the other state resets.
- Rule candidate: When a session teardown cleans up subscription state, also reset any module-level guard flags that were set by the active session so they do not leak into the next session.

### Finding 4
- Severity: low
- Category: test-gap
- Summary: No automated test exercises the runtime behavior of `registerCommandHelpShortcut`, the `commandHelpOpen` guard, or the `while (true)` loop-back flow. Validation is limited to static regex checks.
- Evidence: `scripts/validate-vazir-command-docs.mts` asserts string presence in source code but never calls the functions. There is no scenario that mocks `ctx.ui.onTerminalInput`, fires a Ctrl+? sequence, and asserts input consumption, guard deduplication, or detail-overlay loop-back.
- Recommendation: Add a runtime validation scenario (or extend an existing harness) that mocks the terminal input stream, triggers the shortcut, and asserts that (a) the input is consumed, (b) `commandHelpOpen` flips true then false, and (c) selecting a command loops back after the detail overlay closes.
- Rule candidate: When a feature introduces stateful guards or input consumption, add a regression test that exercises the guard directly rather than only asserting static source patterns.

### Finding 5
- Severity: low
- Category: simplification
- Summary: The `showCommandHelp` overlay does not display keyboard navigation hints, unlike every other Vazir selection overlay.
- Evidence: `showCommandHelp` in `chrome.ts` adds the quickstart banner and `SelectList` to the panel but no hint text. `showSelectionList` in `vazir-ui.ts` explicitly adds `↑↓ navigate • enter select • esc cancel` at the bottom.
- Recommendation: Add a hint line to the `VazirPanel` in `showCommandHelp` so users know how to navigate, select, and exit.
